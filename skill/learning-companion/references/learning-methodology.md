# 学习方法论：可操作规则

本文件把 SKILL.md 里的核心引导词展开成可执行规则。设计自测题、判断该教什么、安排复习节奏时用。

## 储存强度 vs 流畅度

- **流畅度（fluency）**：当下看顺了、跟着敲一遍能跑，产生"我会了"的错觉。
- **储存强度（storage strength）**：过几天还能从记忆里调出来、能迁移到新场景。这才是真目标。
- 流畅度高不代表储存强度高。刚讲完立刻能复述，不等于学会了。
- 建立储存强度靠**合意困难（desirable difficulty）**：让用户付出恰当的回忆努力，而不是把路铺到底。

判据：如果一个练习用户不动脑就能做对，它没有在建立储存强度，加难或换成回忆题。

## 检索练习

- 教完一个点，不要让用户重读，让他**合上材料从记忆里回忆**：说出定义、复述流程、默写关键代码骨架。
- 出题优先"回忆型"而非"再认型"：问"X 是怎么工作的"，而不是给四个选项选一个。
- 回忆卡壳的地方就是储存薄弱点，标记进 `flashcards.md` 加大复习权重。

## 间隔复习

- 新学的点当天检索一次，之后按扩大间隔复习（如次日、三天后、一周后）。
- `flashcards.md` 里给每张卡记"上次复习/下次该复习"，`progress.md` 维护"待复习清单"。
- 每次新课前，先花几分钟检索上次的待复习卡，再进新内容。

## 交错

- 练**技能**时（写代码、做题），把不同但相关的主题混着练，不要同一类型连做十道。
- 交错会让当下感觉更难、正确率下降，但长期迁移和辨别能力更强。
- 学**新知识**的获取阶段不交错——那时难度是敌人，先把单个概念讲清。

## 最近发展区

- 每一步都挑"用户靠现有基础 + 一点帮助能够到"的点，不太易（无聊、不长储存）也不太难（超工作记忆、挫败）。
- 判断方法：读 `learning-records/` 看已掌握什么，读 `MISSION.md` 看目标方向，选二者之间最近的下一个点。
- 用户明确指定要学某点时，尊重用户，但如果跨度太大，先补必要的桥。

## 费曼自检

- 讲完让用户**用大白话给外行讲一遍**这个概念。
- 讲得磕巴、绕回术语、讲不下去的地方，就是没真懂——定位到那里回去补。
- 话术示例："现在假设我完全不懂，你用一句人话告诉我 X 是干嘛的？""如果我问你为什么不用 Y，你怎么答？"
- 用户讲清楚了，才可以写进 learning record（"真正掌握"的证据）。

## 不信任模型记忆

- 涉及具体 API 签名、版本行为、论文结论、项目实现细节时，**不凭记忆讲**。
- 先查一手来源（官方文档 / 源码 / 论文原文 / 规范），讲解里带上引用（链接或文件路径:行号）。
- 不确定的地方明确标"这点需要核实"，不要编一个听起来合理的答案。
- 一手来源的可信度：官方文档/源码/原始论文 > 官方博客 > 高声誉社区 > 随手搜到的二手博客。

## 自测题设计规则

- 每组题至少覆盖：一道概念回忆题、一道应用/设计题、一道排错/追问题。
- 概念题考"是什么、为什么"；应用题考"给个新场景你怎么做"；排错题给一段有问题的代码/推理让用户找错。
- 选择题的选项长度尽量一致，别用格式长短泄露答案。
- 不要一次给完整答案，除非用户请求批改；先让用户答，再针对性纠正。
