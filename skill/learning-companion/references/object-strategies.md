# 分对象学习策略

主流程统一（建图 → 定 Mission → 按最近发展区教 → 检索自测 → 沉淀双链），但四类对象的拆解顺序、关键产物、常见坑、一手来源类型不同。判断当前学的是哪类，加载对应一节。

判断规则：

- 提到某语言名（Rust/Go/Haskell 等）且想能写代码 → 语言。
- 给了论文链接、PDF、arXiv、"这篇"、"paper" → 论文。
- 指向一个仓库路径 / GitHub 链接 / "这个项目" / "这份代码库" → 开源项目。
- 想入门一个领域、范式、技术栈方向（如"RAG""分布式共识""eBPF"）→ 技术方向。
- 无法判断时问一句用户想达到什么。

---

## 一、学一门新编程语言

**拆解顺序**

1. 语言定位与心智模型：它为什么存在、解决什么痛点、和用户已会的语言比最大差异是什么（用已知锚定未知）。
2. MUP（Minimal Usable Program）：环境装好、跑通第一个能运行的小程序，建立反馈闭环。
3. 语法地图：类型系统、控制流、函数、错误处理、并发模型、包管理，各画一个骨架。
4. 该语言的"独特难点"：Rust 的所有权/借用、Go 的 goroutine/channel、Haskell 的 Monad 等，重点死磕。
5. 手写小程序：每个核心概念配一个能运行的小练习，不停手写。

**关键产物**

- 可运行的 MUP 和每概念小练习。
- 语法地图双链笔记（`[[<语言> 类型系统]]`、`[[<语言> 错误处理]]` 等）。
- "坑与惯用法"错题笔记。

**常见坑**

- 只读语法不写代码 → 流畅度错觉。必须手写运行。
- 用旧语言的思维硬套 → 要显式对比差异。
- 一上来抠边角特性 → 先主线后细节。

**一手来源类型**：官方文档、官方 The Book / Tour、标准库源码、官方 playground。不要凭记忆讲 API 签名，查文档。

---

## 二、读一篇论文

**拆解顺序（问题-方法-实验-局限）**

1. 先读 Abstract + Intro + 结论，用一句话说清：这篇解决什么问题、核心 idea 是什么。
2. 问题：为什么这个问题重要、之前的方法差在哪。
3. 方法：核心方法拆成"输入 → 关键步骤 → 输出"，把公式和图对应到直觉。
4. 实验：验证了什么、baseline 是谁、关键指标、消融说明了哪个部件重要。
5. 局限与延伸：作者承认的局限、你能想到的质疑、后续工作。

**关键产物**

- 一句话总结 + 问题/方法/实验/局限四段结构化笔记。
- 核心概念双链笔记，**保留英文术语**（`[[Attention 机制]]`、`[[KV Cache]]`）。
- 针对方法和实验的自测题（"为什么用 X 而不是 Y""这个指标说明什么"）。

**常见坑**

- 逐字翻译当理解 → 要能用大白话讲 idea。
- 只信 abstract 的结论 → 关键结论回到正文和实验核对。
- 凭记忆复述作者结论 → **必须引用原文段落/图表**，不确定就标注。

**一手来源类型**：论文原文（PDF/arXiv）、作者开源代码、被引的关键前作。不用二手解读代替原文。

## 三、啃一个开源项目

**拆解顺序**

1. 架构总览：读 README、docs、目录结构，画出模块划分和它们的关系，说清这个项目"做什么、入口在哪"。
2. 定一条核心链路：和用户一起选一条最能代表项目的主流程（如"一个请求怎么从入口走到响应""一条数据怎么被处理"）。
3. 本地跑通：按官方文档把项目跑起来，建立"能改能验证"的反馈闭环。
4. 顺链路读关键模块：沿选定链路逐个读关键函数/类，边读边在代码里定位，不漫游。
5. 动手改一点：改一个小地方并验证效果，确认真读懂了。

**关键产物**

- 架构总览图 + 核心链路说明。
- 关键模块双链笔记（`[[<项目> 请求入口]]`、`[[<项目> 核心调度]]`）。
- "这段代码为什么这么写"的追问笔记。

**常见坑**

- 从第一个文件顺序读到最后 → 要按链路读，不要漫游。
- 只读不跑 → 必须本地跑通并能改。
- 凭记忆猜实现 → 用 grep/读源码定位真实代码，引用文件路径和行号。

**一手来源类型**：项目源码本身、官方 docs、设计文档/RFC、issue 和 PR 讨论。

## 四、跟进一个新技术方向

**拆解顺序**

1. 全景地图：这个方向要解决什么问题、有哪些主流派别/方案、现在处在什么阶段。
2. 主线概念：抽出 3-5 个绕不开的核心概念，逐个讲清并互相串联。
3. 锚定一手权威来源：找到这个方向公认的权威文档/论文/规范/标杆项目，不追碎片化博客。
4. 最小验证：动手做一个最小 demo 或复现，把概念落到能跑的东西上。
5. 建立追踪：给用户指出该方向持续更新的可信信源（官方博客、关键会议、核心维护者）。

**关键产物**

- 全景地图 + 主线概念双链笔记。
- 一个最小可运行 demo。
- 权威信源清单（沉到 `MISSION.md` 或单独笔记）。

**常见坑**

- 被碎片化二手内容带偏 → 锚定少数权威一手来源。
- 概念停在名词层面 → 用最小 demo 落地。
- 贪多求全 → 先主线 3-5 个概念，其余按需展开。

**一手来源类型**：领域奠基论文、官方规范、标杆开源项目源码、核心团队官方博客。
