# 学习工作区文件格式

有状态模式在当前目录维护这些文件。每个文件给出 `模板` 和 `规则`。建或更新工作区文件时对照本文件。

工作区布局：

```text
<当前目录>/
├── MISSION.md
├── progress.md
├── flashcards.md
├── learning-records/
│   └── 0001-<dash-name>.md
└── notes/
    └── <双链笔记>.md
```

---

## MISSION.md

锚定用户为什么学。一个工作区一个 Mission，控制在一屏内。

### 模板

```markdown
# 学习 Mission：<对象>

## 为什么学
<用户学这个的真实理由，具体不空泛>

## 成功长什么样
<能做出/看懂什么，才算达成>

## 约束
<时间、已有基础、可用资源等>

## 范围外
<明确这次不学什么，避免发散>
```

### 规则

- Mission 含糊时先追问，别替用户填。
- 用具体场景而非抽象目标（"能读懂 vLLM 的调度代码"优于"了解推理框架"）。
- Mission 变化时更新本文件并加一条 learning record，改动前和用户确认。

---

## progress.md

跨会话的进度指针。每次会话结束前更新。

### 模板

```markdown
# 学习进度：<对象>

## 已学
- <日期> <学了什么，链接到相关 learning record>

## 当前位置
<现在学到哪，用一两句说清>

## 下一步
<下次该学什么，为什么是这个>

## 待复习
- [ ] <闪卡/概念> —— 下次复习：<日期>
```

### 规则

- "下一步"必须具体到一个可执行的学习单元，不写"继续学"。
- "待复习"和 `flashcards.md` 联动，新课前先清待复习项。
- 用户只说"继续"时，这是重建上下文的第一入口。

---

## learning-records/NNNN-<dash-name>.md

记录用户**真正掌握**或**纠正过的认知**，类似架构决策记录。用于算最近发展区。

### 模板

```markdown
# LR-NNNN：<一句话标题>

- 日期：<YYYY-MM-DD>
- 状态：有效 <或 "被 LR-MMMM 取代">

<用户掌握/纠正了什么，一段话即可。可写触发它的证据：用户能讲清了 / 暴露了先验知识 / 纠正了误解 / Mission 变了。>
```

### 规则

- 编号从 0001 递增，dash-name 用短横线。
- 只在有真实"学会/纠正"证据时写；覆盖了内容 ≠ 学会了。
- 认知被推翻时不删旧记录，用 `状态：被 LR-MMMM 取代` 标注，新开一条。
- 单条可以很短，一段话就够。

---

## flashcards.md

检索练习和间隔复习的卡片。

### 模板

```markdown
# 自测闪卡：<对象>

## <概念/主题>
- Q：<问题>
  A：<答案>
  上次复习：<日期> ｜ 下次复习：<日期> ｜ 掌握度：<生/熟>
```

### 规则

- 优先回忆型问题（"X 怎么工作"），少用再认型（选择题）。
- 卡壳的卡把"掌握度"标"生"，缩短下次复习间隔。
- 一组卡覆盖概念回忆 / 应用设计 / 排错追问三类。
- 卡片答案不在提问时直接暴露；用户先答再看。
