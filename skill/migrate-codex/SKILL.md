# Codex 迁移与恢复

先区分云端账号数据、本地 Codex 状态和实际工作文件。确认源/目标、系统、版本、有效 CODEX_HOME，以及目标是否已有需要保留的会话；能从现有证据确定的事项不重复询问。

## 清点与方案

- 用随附 `scripts/audit.py --home <数据目录>` 清点 JSONL 和 `.jsonl.zst`、索引 ID、数据库表计数和会话文件对应关系。脚本只读取源文件，在临时副本上查 SQLite，不读取认证文件或输出消息正文；运行中的数据库清点只能作为初步证据。
- 查实际生效的数据目录，不只套默认 `~/.codex`。工作区、产物、项目源码及未提交修改另列清单；同账号不代表本地文件已同步。
- 根据本机版本及官方文档核对状态文件；不要把数据库编号、列名、迁移校验值当成跨版本稳定 API。
- 常规迁移先读 [迁移流程](references/workflow.md)。只有需要修改会话文件、分页历史或分卷关系时，读 [分卷与位置约束](references/rollouts.md)。

## 执行原则

已有迁移授权时完成备份、映射、冲突处理和副本验证，再进入实际写入。保留目标新数据与当前系统登录状态；不要整目录覆盖活跃的 CODEX_HOME。

优先使用当前安装提供的受支持导出/恢复接口；没有经核实的接口时，为本次结构准备可审查的离线合并。手工冷备份和写入前停止相关写入者，或采用能保证一致性的 SQLite backup API。不要遗漏未检查点的 WAL，不手工删除活动数据库旁车文件。

路径转换只作用于已确认的结构化路径字段。保留历史消息、命令和代码；项目移动过位置时按存在性映射。跨系统保留目标运行时，不搬 Windows 二进制到 Mac，也不默认启用旧自动化、排队动作或远程控制身份。

## 验收与交付

分别核对数据库完整性、关系、普通/归档/长会话正文、图片、项目归属和目标已有数据。可使用隔离 CODEX_HOME 下的当前 app-server 读取验证，但方法和参数要以当前协议为准；验证不发起模型任务或外部动作。恢复写入后检查应用中的可见性，并在授权范围内验证续聊与工作区访问。

文件数、数据库记录数、索引 ID 数和 UI 聊天数可以不同。报告每个数字的范围、时间及阶段，不能把子会话当独立用户聊天，也不能把副本验证写成生产环境已验收。交付备份位置、执行结果、未恢复项和可回滚方式；用户需退出当前应用才能继续时，先把离线脚本准备并验证好。
