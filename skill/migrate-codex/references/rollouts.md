# 仅在需要重写会话文件时读取

保留原始文件和所有历史消息。能通过显式恢复参数或受支持接口重新指定工作目录时，优先验证该方式；不能为调整路径直接重写整个历史而忽略相关索引。

本次案例的关键约束：

- `.jsonl.zst` 同样是会话文件。先核对当前版本是否支持透明读取；解压不是迁移的普遍前提。
- 线程 ID 不一定等于分卷 ID。文件名可能同时带线程 ID 和新的分卷 ID；不能只用 session_meta.id 标识每一个物理分卷。
- 文件中可能有复制自父线程的后续 session_meta，不能让它覆盖首部的拥有者信息。
- 某些版本用 history_base 引用前一分卷，并记录截止 ordinal 和字节偏移。历史位置还可能在 thread_turns、projection 等结构中。
- ordinal 与字节偏移不是同一概念。重写一行会改变后面位置的字节偏移，即便行数和 ordinal 不变。
- 如果确实改写：建立每个物理分卷的“原始位置→新位置”映射；按引用链修正 cutoff；将每轮的开始/结束位置定位到正确的祖先分卷，而不是一律套当前分卷的映射。以当前代码/协议核实边界是否 exclusive。
- 分卷间引用的数字长度变化也可能再次改变位置，需用依赖顺序或收敛检查计算，不能只改一遍数字。
- 验证分卷存在、引用无环、位置不越界并落在有效边界。不要用截断、清空历史或随意钳制偏移消除错误。
- 除 session_meta/turn_context 外，分页历史条目的图片 savedPath 等字段也可能是平台相关绝对路径。只修改已确认的路径元数据；禁止对消息文本、工具命令、代码做全局替换。

故障线索包括 missing source rollout、cutoff byte offset is past the source rollout、AbsolutePathBuf deserialized without a base path。它们指向不同层次，不应靠删索引或反复重装处理。

验收用完整分页读取覆盖较早历史，不仅打开最近三轮。保留原始文件、修复映射及结果，标注当前版本；字段名、文件命名、API 都应现场确认。
