# 清点、合并与验收

## 清点真实状态

默认 home 是 `~/.codex`，也可能被 CODEX_HOME 或不同执行环境改变。先确认当前应用/CLI 实际使用位置和版本。登录相同 ChatGPT 账号及组织与本地状态恢复分别检查。

检查 sessions、archived_sessions 中未压缩及压缩文件，session_index.jsonl、全局桌面状态、根目录 SQLite 数据库及旁车文件；不要输出 auth.json、令牌或私密消息。索引只提供线索，不能从索引伪造正文。发现原始复制缺数据库时，优先补齐源机原数据，不立即重建空索引。

## 一致备份与传输

手工复制前退出桌面端、相关 CLI/编辑器及其他写入服务；复制数据库时保留对应 WAL。若使用 backup API，验证生成副本的完整性。SHM 是协调文件，不是会话正文，但不要在仍有写入者时随意处置旁车文件。

Windows ZIP 成员可能使用反斜杠。先统一成员分隔符，拒绝绝对路径、盘符和 `..` 越界，再解包到独立目录。核对 ZIP、文件清单、数据库及传输前后哈希。

## 合并现场数据

建立源根目录到目标根目录的显式映射，核实文件夹实际位置与大小写。包含 Documents/Codex、自定义源码目录和其他资料目录，不能仅替换用户名或盘符。

目标已有数据时，先备份，再用目标当前版本的 schema 在副本中按主键导入。检查依赖表的顺序、约束及新旧 ID 冲突。保留目标已存在记录；对冲突给出具体处置，不能用宽泛忽略掩盖错误。不要覆盖数据库迁移校验表，也不要复制旧机器的设备身份、活跃队列和凭据。

项目和置顶可能还存在旧 ID 到新 ID 的映射、桌面状态与数据库之间的迁移关系。只按证据恢复显式关系，不能凭 cwd 将所有聊天强制归入项目。保留目标自己的界面偏好，除非用户要求恢复旧布局。

实际工作文件另行合并；冲突保留目标，旧副本单独留存。Git worktree、未跟踪文件、附件、技能和生成图片都要按实际范围检查，不只拷 Git 已提交文件。

## 最后写入和验收

离线脚本应检查写入者、在执行时读取目标最新数据、先做一致备份再安装、发生失败尝试恢复，并记录完成结果。不能为了方便静默终止无关会话。若当前聊天所在应用必须退出，交付可运行的脚本及清楚的退出/重开步骤。

验证至少包括普通会话、归档、分页长会话、分卷/分叉、图片、项目和目标已有会话。完整性检查通过后还要实际读取。根据任务范围做一次续聊或项目访问，不自动执行历史工具命令。

官方入口（使用时核对当前内容）：
- https://learn.chatgpt.com/docs/config-file/config-advanced#config-and-state-locations
- https://learn.chatgpt.com/docs/reference/troubleshooting#feedback-and-logs

2026-10 的一次实测存在 state_5.sqlite、thread_history_1.sqlite 等；这是案例版本信息，不是固定文件清单。

## 清理迁移副本

删除中转目录前区分当前使用的 home/工作区与只读源副本。检查数据库项目根目录、会话路径、有效配置及符号链接；消息或输入历史中出现旧路径并不等于运行时依赖。逐文件核对迁移结果，另查根目录隐藏文件与 Git 历史。补充导出包未必包含原目录的配置、技能、认证或其他资产；清理原 home 副本前保留完整备份清单及校验。用户仅询问能否删除时先给结论，不据此执行删除。
