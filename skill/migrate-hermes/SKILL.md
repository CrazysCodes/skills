# Hermes Agent 迁移与恢复

确认源/目标系统、Hermes 版本、有效 HERMES_HOME、profile、执行方式及目标现有数据。Windows 数据可能在 LOCALAPPDATA/hermes，也可能使用其他 home；不要看到用户目录下有 .hermes 就认定它是主要目录。

## 备份与恢复

- 先读 [恢复与自检流程](references/workflow.md)。使用时核对当前 `hermes backup --help`、`hermes import --help` 和官方文档。
- 优先官方完整 backup，检查退出码、ZIP、state.db 和文件清单，再核对传输哈希。quick 模式不是完整迁移；目标已有重要历史时，先备份并在隔离目录/profile 验证。
- import 是覆盖恢复，不是新旧历史的自动合并；不能把 `--force` 理解为合并选项。按照现有迁移授权处理明确的恢复范围，有冲突或需要覆盖未授权新数据时再澄清。
- 导入前停止目标会话、gateway、serve、桌面端及其他写入者。不要跨平台复制旧 venv、解释器、二进制和系统服务启动器来替代安装。

## 自检与修复

随附 `scripts/audit.py --home <数据目录>` 只读取源文件，在临时数据库副本上统计 sessions/messages、技能、任务状态及指定 CLI 的可发现性。它不读取凭据内容，不执行任务，不保证运行中数据库的复制一致性。

导入后核对 doctor、会话列表和历史正文，检查实际 profile 与终端工作目录。工具链问题按 [环境修复](references/environment.md) 排查：版本、PATH、解释器、凭证、字体、扩展及平台路径都要分开核实。

任务清单应区分存在、暂停、启用和定义缺失。缺失定义可从旧备份或会话历史寻找依据，但恢复定时发送/发布前沿用用户原授权范围，不因恢复环境而自动执行外部动作。

## 验收与记录

数据库计数、消息计数、逻辑聊天和压缩/父子会话可能不同；与同一时间点的备份比较，不能把后续计数变化直接判为丢数据。配置文件体积变小也不能直接判为丢配置，应比较生效字段。

按用户业务验证读取、生成文件、登录状态、gateway 路由及任务定义。写文档、发送消息、发布内容等有外部影响的验收沿用已有授权；缺授权时可先准备本地结果或检查只读状态。

报告已恢复、已验证、待重新登录及未启用项，附备份和回滚位置。先隔离残留再处理，不直接清理尚未证明无用的 WAL、锁文件或旧凭据。分享记录应移除密钥、账号、私人路径和备份下载链接。
