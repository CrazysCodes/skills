# 作品体检报告模板

删去占位说明后填写，不把未执行检查写成完成。读者优先看到表现、影响与下一步，技术证据随后。

## 开头

> 在【已检页面与任务、环境】中，【用途】的表现为【有证据支持的评价】。优先处理【问题】；【重要未检查能力】仍未验证。

基本信息：URL / 时间与时区 / 网站版本（未知可写未知）/ 规则 1.0.0 / 当前实测或历史证据重放 / 用途及推断置信度。

计划与范围：选择页面、1–3 个核心任务、尺寸/引擎、正常/异常状态、授权范围。列实际完成与计划差异。工具/版本/网络与数据窗写清。

## 八维结果

| 维度 | 结论 | 通过/发现问题/未验证/N/A | 抽样范围与一句说明 |
| --- | --- | --- | --- |
| 用途与内容 C | 按 rubric | 0/0/0/0 | 事实和评估判断分开 |
| 视觉层级 V | 按 rubric | 0/0/0/0 | 没截图就不能视觉通过 |
| 功能与反馈 F | 按 rubric | 0/0/0/0 | 页面可达与任务成功分别写 |
| 移动与兼容 M | 按 rubric | 0/0/0/0 | 标模拟/真机、引擎 |
| 性能 P | 按 rubric | 0/0/0/0 | field/lab、URL/origin、数据窗 |
| 可访问性 A | 按 rubric | 0/0/0/0 | 自动与人工覆盖，不作完整认证 |
| 可发现与分享 D | 按 rubric | 0/0/0/0 | 按公开/私有意图 |
| 公开安全与隐私 S | 按 rubric | 0/0/0/0 | 配置事实不是整体安全评级 |

维度结论使用：优先修复 / 证据不足 / 可改进 / 已检范围良好 / 不适用，严格按 rubric。每维标完整抽样、部分抽样或未检查。分母是规则数量，重复实例不重复计数；覆盖信息只说明检查工作，不当作质量分。

## 关键任务

| 任务 ID | 起点、输入及预期结果 | 实际操作与观测 | 结论 | 证据 |
| --- | --- | --- | --- | --- |
| T01 | 先写预期 | 写执行了什么 | 通过/问题/未验证 | 页面、轨迹、文件 |

未实际提交的表单任务、没有正确答案的计算任务分别说明边界。状态规则可有多个实例。

## 最值得先做的 1–3 件事

每条说明对用户的具体影响，按优先级排序。没发现确证问题可以说没有，不凑数。

### 问题 Q01

- 规则：如 A02；跨维度相关时复用同一 Q ID。
- 类型：观察事实 / 评估判断；可信度：已复现 / 待复核。
- 优先级：P0–P3，说明影响、范围、发生条件及恢复方式。
- 位置：URL + 文案/DOM/截图位置；有源码且已读时可附 file:line。
- 复现：起点、环境、步骤。
- 预期：标准原文适用阈值或事先约定的任务结果。
- 实际：实测值、截图或响应片段。
- 影响：作者能理解的使用后果。
- 修复目标：要求什么结果；未经源码证实不指定根因。
- 复测：同场景步骤、阈值、关联功能回归。
- 来源：标准/工具版本/自定义规则。

待复核项不混入确证缺陷；保留复核动作。

## 做得好的地方

写具体行为与证据，避免“安全很好”“代码卫生满分”之类范围过大的表述。

## 未知与需要补充的证据

列未检查的页面、设备、状态、field 数据、账号/后端能力。N/A 列理由。可继续做的独立检查不等待作者回答；确需决策/测试数据时把问题缩小到影响下一步的具体选择。

## 可复制给 coding agent 的任务

```text
修复 Q01（规则 ID / 优先级）：
页面与可见位置：
已观察证据：
希望达到的行为/阈值：
约束：保持已有用途与关键流程；不要仅为增加文件/消除警告改架构。
验收：重复以下原始场景……；记录结果和未验证项。
不要宣称提高指定分数或完整标准通过，除非实际复测支持。
```

## 证据附录

- 工具报告、截图、原始结果路径、关键命令和配置。
- 每条规则的状态及适用理由，尤其是未验证/N/A。
- 测试工具失败、网络错误和已排除的误报。
- 历史证据的采集日期、原始环境；本次只做重评时不要写“今天实测”。

## 修复后的报告

保留规则、问题 ID、任务与环境；列已修复/仍存在/无法验证、最新证据与回归结果。不重复运行无关通过项；大幅改动才扩大范围。
